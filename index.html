How I work

  • I write the structure of a problem as a document before I write code. In my repositories the spec is the source of truth, not the implementation.
  • I keep what is measured separate from what is only assumed, in writing.
  • I keep unresolved risks inside the repository rather than outside it. The open questions and untested acceptance criteria of the projects above are still there.
  • I would rather be wrong cheaply and correct fast than be right late.
  • I set the objective, the constraints and the verification criteria; the agent writes code and tests; I review the diff.
